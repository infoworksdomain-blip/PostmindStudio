## Bugs found and fixed (each with a test written alongside)

1. FIXED `/robots.txt` and `/sitemap.xml` returned 404 on production. Added `src/app/robots.ts`,
   `src/app/sitemap.ts`, `src/lib/seo/site.ts` (origin from `APP_URL`). Sitemap: home, pricing and
   the six legal pages. Robots disallows `/api/`, every signed-in page prefix, `/p/` and `/meta/`.
   Tests: `src/app/seo.test.ts` (5), `e2e/seo.spec.ts` (2).
2. FIXED Create, "Plan a month", onboarding first video and the project Generate button stayed
   enabled when the organisation was read-only or had no plan, so a click gave no on-screen reason.
   `src/components/studio/account/create-access.tsx`: the buttons are disabled, `aria-describedby`
   points at the reason, and an inline notice with a billing link says "Your account is read-only.
   Update payment to create videos." (or "Choose a plan to create videos."). A plan-less
   organisation can still draft a slideshow, as the server allows. The server access gate is
   unchanged. Tests: `create-blocked.test.tsx` (3), `plans.test.tsx` (1). Six new strings in 11
   locales.
3. FIXED Reference library search listed the nearest videos with a weak percentage for a query
   with no real match. Added a relevance floor (`library/relevance.ts`, `MIN_SIMILARITY = 0.25`;
   a title or tag word still matches) and a "No close matches for “…”" state with category
   buttons. Tests: `relevance.test.ts` (3), `library-browse.test.tsx` (1), `test/api/library-search.test.ts`
   (new case, and the old "unrelated item ranks last" assertion now says it is dropped; DB-gated, CI).
4. FIXED Approval workflow cards showed raw business ids ("Applies to business biz_1"). They show
   the business name. Test: `approvals.test.tsx` (2).
5. FIXED (demo) a one-word brief ran through to a rendered video. The simulated pipeline now stops
   in DRAFT with `brief_too_vague` and three directions, using the same `isVagueBrief` rule as live;
   choosing a direction runs it and it never asks twice. Test: `test/unit/demo-vague-brief.test.ts` (3).
6. FIXED (demo) stock images were attributed to Pexels and Storyblocks. All are Pixabay, with the
   Pixabay Content License note and a pixabay.com page link. Test: `demo-stock-pixabay.test.ts`.
   Live check: the real attribution line is built from the providers of the images shown
   (`image-grid.tsx`), so it can only name a provider whose images are in the library.
7. FIXED (demo) Admin Centre said legal documents were placeholders and sign-up closed. Now ready
   and open. Test: `demo-legal-ready.test.ts`.
8. FIXED (demo) reference search used the same floor; two luxury-car sample videos added so
   "luxury cars" matches. Test: `demo-library-search.test.ts` (4).

The demo was rebuilt with `node scripts/demo/build.mjs` in this worktree
(`demo/dist/postmind-studio-demo.html`). The demo served on port 3021 comes from the other
worktree and needs the same rebuild after this branch merges.

## Found but not fixed

- The approval workflow form still asks the owner to type raw business ids (comma-separated);
  only the display was fixed. Needs a business picker.
- The demo's public legal pages render the repository's draft texts (with `[[…]]` fill-in markers
  and a draft banner), unlike live, which has the finished text. Left alone: the demo cannot
  carry the operator's final legal text.
- The demo's access-gate copy (`demo/api/billing-access.ts`) lacks the `/content-plans` spend
  routes the real gate lists, so a read-only demo organisation can still plan a month at the API
  level (the button is now disabled in both).
- `MIN_SIMILARITY = 0.25` is a judgement for text-embedding-3-small; confirm on the real corpus.
